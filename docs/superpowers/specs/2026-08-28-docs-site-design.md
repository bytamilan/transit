# Transit docs site — design spec

Date: 2026-08-28
Status: approved

## Goal

Publish a GitHub Pages documentation site for the Transit monorepo covering:
overview/features, per-app screenshots (real, checked-in golden/Playwright
images), per-package reference docs, the REST API (from
`contracts/openapi.yaml`), and a "wiki" section (ADRs, onboarding, runbooks)
republished from `internal-docs/`.

## Non-goals

- No hand-duplicated content: everything the site republishes (ADRs,
  onboarding, runbooks, package READMEs) stays sourced from its existing
  location and is copied in at build time, not authored twice.
- CI does not regenerate screenshots on every push. Golden/Playwright images
  are checked into git like any other test fixture and only regenerated when
  someone re-runs the local scripts (e.g. after a screen changes).
- No changes to app behavior — this is docs/tooling only.

## Site generator

**MkDocs Material.** Chosen over Docusaurus (heavier, React/MDX not needed
here) and plain Jekyll (weak API-doc/search story). Config lives at
`docs-site/mkdocs.yml`, content at `docs-site/docs/`.

## Directory layout

```
docs-site/
  mkdocs.yml
  requirements.txt              # mkdocs-material pin
  scripts/
    sync_docs.py                # copies internal-docs/* and packages/*/README.md into docs/
    build_api_docs.sh           # runs @redocly/cli against contracts/openapi.yaml
  docs/                         # generated + authored; sync targets are gitignored
    index.md                    # authored: overview (from README)
    features.md                 # authored: feature breakdown
    apps/
      rider_app.md              # authored: description + embedded golden screenshots
      driver_app.md
      portal.md                 # authored: description + embedded Playwright screenshots
    packages/                   # generated by sync_docs.py from packages/*/README.md
    wiki/
      adr/                      # generated from internal-docs/adr/*.md
      onboarding.md             # generated from internal-docs/onboarding/README.md
      runbooks/                 # generated from internal-docs/runbooks/*.md
    api/
      index.html                # generated by build_api_docs.sh (ReDoc static build)
    assets/
      screenshots/
        rider_app/*.png         # copied from apps/rider_app/test/golden/goldens/
        driver_app/*.png        # copied from apps/driver_app/test/golden/goldens/
        portal/*.png            # copied from docs-site/scripts/portal-shots output
```

Only `index.md`, `features.md`, and `apps/*.md` are hand-authored and
committed as real source. `packages/`, `wiki/`, `api/index.html`, and the
screenshot copies under `assets/screenshots/` are build outputs — gitignored
under `docs-site/docs/`, regenerated by `make docs` / CI. The screenshot
*source* PNGs (golden test images) are committed under each app's `test/`
directory, and Playwright output is committed under
`docs-site/scripts/.portal-shots/` — those are the real artifacts; the copies
under `docs-site/docs/assets/` are just staging for the mkdocs build.

## Screenshots

### Flutter golden tests (rider_app, driver_app)

New test files under `apps/<app>/test/golden/`, one per screen, using
`ProviderScope(overrides: [...])` with fixture data so screens render without
network/Supabase:

- rider_app: splash/agency_select, about, planner (with fixture itinerary),
  stop (with fixture arrivals), home and route (chrome only — MapLibre is a
  platform view and renders blank in `flutter test`, so these goldens capture
  the surrounding UI, not live map tiles).
- driver_app: splash, login, onboarding, duty (fixture duty list), active
  shift (fixture trip), transparency.

Golden images live at `apps/<app>/test/golden/goldens/<screen>.png`,
generated with `flutter test --update-goldens test/golden/`. Checked into
git — future `flutter test test/golden/` runs (no `--update-goldens`) diff
against them, so they also function as regression tests, not just doc
assets.

### Portal (Playwright)

`docs-site/scripts/portal_shots.mjs` — Playwright script that:
1. Assumes `make dev-full` is already up (migrated + seeded via
   `infra/supabase/seed/demo_agencies.sql`).
2. Logs in as the seeded demo user through the real login form.
3. Navigates to and screenshots: login, datasets (public), admin home,
   dispatch board, vehicles, routes, roster, alerts, incidents, api-keys.
4. Writes PNGs to `docs-site/scripts/.portal-shots/`.

This is run manually/locally (`make docs-goldens` triggers both the Flutter
golden update and this script) — not part of the docs CI build, since it
needs a live stack.

## API reference

`docs-site/scripts/build_api_docs.sh` runs
`npx @redocly/cli build-docs ../contracts/openapi.yaml -o docs/api/index.html`.
MkDocs Material accepts a direct link to a static `.html` file in `nav:`, so
`docs-site/docs/api/index.html` is linked as a normal nav entry — no plugin
needed.

## Wiki

`sync_docs.py` copies (verbatim, no rewriting) into `docs-site/docs/wiki/`:
- `internal-docs/adr/*.md` → `wiki/adr/`
- `internal-docs/onboarding/README.md` → `wiki/onboarding.md`
- `internal-docs/runbooks/*.md` → `wiki/runbooks/`

Internal relative links between these files continue to work since relative
structure is preserved.

## Packages

`sync_docs.py` copies each `packages/<name>/README.md` →
`docs-site/docs/packages/<name>.md`, prefixing an mkdocs-friendly H1 if the
source README doesn't already start with one. `transit_api_client` also gets
a note linking to the API reference page, since its generated client docs
(`packages/transit_api_client/doc/*.md`) mirror the OpenAPI spec — not
duplicated into the site.

## Build & deploy

- `docs-site/requirements.txt`: `mkdocs-material`.
- `make docs` — runs `sync_docs.py`, `build_api_docs.sh`, `mkdocs build`
  (from repo root, wraps `docs-site/`).
- `make docs-serve` — same sync/API steps, then `mkdocs serve` for local
  preview.
- `make docs-goldens` — regenerates Flutter goldens (`--update-goldens`) and
  runs the Playwright portal script (expects `make dev-full` already
  running).
- `.github/workflows/docs.yml` — on push to `main` touching
  `docs-site/**`, `internal-docs/**`, `packages/*/README.md`,
  `contracts/openapi.yaml`, or `apps/*/test/golden/goldens/**`: installs
  Python + Node, runs `make docs`, uploads via
  `actions/upload-pages-artifact`, deploys via `actions/deploy-pages`.

## Manual one-time step (not automatable here)

Repo Settings → Pages → Build and deployment → Source: **GitHub Actions**.
Without this the `deploy-pages` job will fail even though the build
succeeds. Flagged to the user at the end of implementation.

## Testing / verification

- `mkdocs build --strict` locally (fails on broken links/nav references).
- `flutter test test/golden/` in each app passes against checked-in goldens.
- Manual: open `mkdocs serve` output in a browser, spot-check nav, API page,
  and screenshot rendering.
